可以，直接把这一层定成 **Technical Contract V0.1**。从这里开始，后面的 Engine、ContentLoader、Validator、DebugPanel 都以这份契约为准。

我先锁几个工程约定：**TypeScript 和 YAML 都使用 camelCase 字段；ID 一律 `snake_case`；所有枚举在 YAML 中直接使用 TypeScript 枚举字符串；内容文件永远不允许写 JavaScript 表达式。**

# 一个重要决定：State 不使用 `Set`

虽然从程序设计来说：

```ts
Set<string>
```

很好用。

但我们第一版全部使用：

```ts
string[]
```

原因是：

```text
GameState
↓
JSON.stringify()
↓
LocalStorage
```

可以直接保存。

否则每次存档还要做序列化转换。

# Event Schema

23:30敲门：

```yaml
schemaVersion: 1

id: event_knock_2330

name: 23:30敲门

trigger:
  type: TIME
  atMinute: 20

conditions:

  op: ALL

  conditions:

    - op: EVENT_TRIGGERED

      # 正式内容里更推荐用 NOT：
```

正确形式应该写：

```yaml
conditions:

  op: NOT

  condition:
    op: EVENT_TRIGGERED
    eventId: event_knock_2330
    scope: CURRENT_LOOP
```

实际上由于：

```yaml
repeat:
  policy: ONCE_LOOP
```

已经能防重，所以甚至可以不写这个 Condition。

最终推荐：

```yaml

name: 23:30敲门

trigger:
  type: TIME
  atMinute: 20

priority: 80

mode: INTERRUPTING

visibility: VISIBLE

repeat:
  policy: ONCE_LOOP

effects:

  - type: SET_FLAG
    key: knockTriggered
    value: true

presentation:

  variants:

    - priority: 100

      when:
        op: CURRENT_LOCATION_IS
        locationId: warehouse

      blocks:
        - knock_heard_from_outside

    - priority: 50

      when:
        op: CURRENT_LOCATION_IS
        locationId: corridor

      blocks:
        - knock_heard_from_inside

    - priority: 10

      when:
        op: CURRENT_LOCATION_IS
        locationId: guard_room

      blocks:
        - npc_a_reacts_to_knock
```

这一点非常重要：

> **同一个 Event，只有一份逻辑；根据玩家所在位置选择不同 Presentation。**

# 还有两个我现在建议直接锁死的工程规则

**第一条：Resolver 不修改 State。**

例如：

```ts
sceneResolver.resolve(state)
knowledgeResolver.evaluate(state)
```

`evaluate` 可以返回：

```text
应该发生什么变化
```

真正写 State 的只能是：

```text
EffectEngine
GameController
LoopManager
```

尽可能防止“读状态时偷偷改状态”。

**第二条：所有改变必须可记录。**

禁止：

```ts
state.world.flags.x = true;
```

业务代码直接这么写。

应该走：

```ts
effectEngine.apply({
  type: "SET_FLAG",
  key: "x",
  value: true,
});
```

这样以后才能做到：

```text
Debug Log
Undo
Replay
State Diff
自动测试
```

这对我们这种状态驱动游戏价值非常高。
